# 서버 카탈로그 비교 분석

사용자 요청에 따라 기존 국내 온톨로지 작업물을 먼저 Git 별도 브랜치에 보존하고,
실제 분석의 입력은 기존 `wanted-atlas` 서버 DB로 전환했다. 분석 범위는 사용자가
선택한 **국내외 전체 포털 비교**다.

- 기존 작업 보존 커밋: `cf35f5f` (`codex/server-catalog-analysis-20260915`)
- 기존 공유 페이지: https://chlsuun.github.io/public-data-ontology/
- 서버 분석 입력: 기존 컨테이너의 `/data/catalog.sqlite3`
- 1차 분석 결과: [결과 보고서](20260915/REPORT.md), [비교 화면](20260915/index.html), [집계 JSON](20260915/report.json)
- 후속 명세 검토: [연결 단서 검토 후보](20260915/review-candidates.json). 실제 데이터셋 쌍이나 승인 관계가 아닌 검토 시작점이다.
- 유형별 QA 초안: [qa-policy.json](qa-policy.json). 공통 기재율과 사이트별 필수 명세 검증을 구분한다.

## 이번에 실제로 분석하는 것

1. **수집 범위**: 포털별 등록정보 수, 국내·해외 비중, 저장된 수집 상태와 중복 표시.
2. **메타데이터 확보 수준**: 제목·설명·제공기관·출처 링크·형식·라이선스·지역·기간 등 항목의 기재율.
3. **날짜 정보**: 명시된 수정일의 파싱 가능 여부, 미래 날짜, 최근 365일 수정일 기재 비율.
4. **개념 분류**: 저장된 주제 분류, 미분류, 복수 분류, 승인 상태와 검토자 식별 정보.
5. **연결 후보**: 포털 간 주제 분포 유사도, 같은 자료에 붙은 주제의 동시 출현,
   설명문에 명시된 행정구역 코드·좌표·단위 관련 단서.

통계적 상관관계나 인과관계 검증은 하지 않는다. 이번 입력의 분석 단위는
**데이터셋 등록정보 한 건**이며, 인구·실업률 같은 실제 관측값 한 행이 아니다.
같은 주제가 많이 붙어 있다는 사실과 실제 변수 간 상관관계는 구분한다.

## 분모와 점수

- 원시 등록 수는 DB의 모든 행을 센다.
- 내용 비교에서는 서버가 `metadata.duplicate_of`에 JSON null이 아닌 값을
  저장한 행을 제외한다. 기존 서버 화면의 규칙이며,
  이번에 출처 간 중복을 새로 판정하거나 제거한 것은 아니다.
- 국내·해외는 출처의 `country` 값으로 나눈다. 해당 자료가 다루는 지역의 구분은 아니다.
- `미상`, `제공처 확인`, 공백 등은 유효한 기재로 세지 않는다.
- 이 검사는 사전에 정한 기본 미확인 표기만 제외한다. 미확인 코드 URL·구분자만 있는 문자열 등의 의미까지 검증한 비율이 아니다. 실제 사례는 [해석상 검토 항목](20260915/interpretation-flags.json)에 남겼다.
- `native_id` 기재율은 그 이름의 필드만 측정한다. `external_id`·DB 기본 키 등 다른 식별자의 존재 여부를 대신하지 않는다.
- 0~10점은 **저장된 메타데이터 기재 점수**다. 제목·설명·제공기관·원문 URL·형식·
  라이선스·지역·기간의 8개 항목을 같은 비중으로 평균한다.
- 원자료 정확도·신뢰도·결측률·재사용 허가 점수가 아니다. 자료 유형에 따라
  기간·지역이 적용되지 않을 수 있으며, API 수집기별 생략 차이도 있으므로
  이 점수로 포털 자체의 우열을 판단하면 안 된다. 사이트별 필수항목 QA는 후속 검토 항목이다.
- 수정일은 메타데이터에 적힌 값이다. 최근 수정되었다고 관측값까지 최신인 것은 아니다.
- 링크는 HTTP(S) 표기만 확인하며 접속 성공 여부를 재검사하지 않는다.
- 주제 분포 코사인 유사도는 분류 분포의 닮은 정도다. 결합 가능성이나 통계적 상관계수가 아니다.
- `approved`는 서버의 저장 상태다. 검토자 필드가 있어도 실제 사람의 검토를 확인한 것은 아니다.

## 실행과 검증

Python 표준 라이브러리만 사용한다. 서버 프로그램을 import하지 않고 DB를
`mode=ro`, `query_only=ON`으로 열어 하나의 읽기 트랜잭션 안에서 순차 처리한다.
DB 캐시는 16MiB로 제한한다. 분석은 낮은 CPU 우선순위로 시작했으며 이번 실행은
2026-09-15 20:17 KST부터 해당 분석 프로세스만 일반 우선순위로 전환했다. 서버 코드·
관계·분류·자료를 수정하거나 수집기를 재시작하지 않는다. 로컬에는 집계 결과만 저장한다.

```powershell
python scripts/test_server_catalog_analysis.py
python scripts/run_server_catalog_analysis.py --host ubuntu@SERVER --identity "$env:USERPROFILE\.ssh\wanted" --host-volume /var/lib/docker/volumes/wanted-atlas_atlas-data/_data --output analysis/server-catalog/20260915/report.json
python scripts/render_server_catalog_analysis.py analysis/server-catalog/20260915/report.json
```

SSH 호스트와 키는 기존에 승인된 연결 정보를 사용한다. 비밀키·인증정보·전체 DB는
결과물에 포함하지 않는다. 실행 스크립트 SHA-256, 읽은 행의 SHA-256, SQL 집계 대조,
분석 시각과 분모를 결과 JSON에 남긴다. 행 해시는 SQLite 파일 전체의 해시가 아니다.

앱 배포로 컨테이너가 교체돼도 영향을 받지 않도록 실제 분석은 호스트의 해당 Docker
데이터 볼륨을 읽는다. 호스트·볼륨 경로는 실제 서버에서 확인한 값을 사용한다.
초기 컨테이너 내 집계는 2026-09-15 20:02 KST 컨테이너 교체로 종료됐으며,
미완료 집계를 결과로 쓰지 않고 호스트에서 새 읽기 스냅샷으로 재실행했다.

소규모 검증에서는 미확인 값 처리, 잘못된 날짜와 미래 날짜, 중복 분모,
거절된 분류 제외, 검토자 없는 승인, 자료가 없는 포털 처리, DB 원본 보존을 확인한다.

기존 국내 수집 DB·공유 그래프와 서버 카탈로그는 별도 스냅샷으로 유지한다.
이번 비교 결과를 기존 `model.json`의 확정 관계로 자동 반영하지 않는다.
